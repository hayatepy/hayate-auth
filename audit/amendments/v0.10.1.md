# v0.10.1 security-review amendment

This amendment supersedes v0.10.0 as the active review target without deleting
either the signed v0.9.1 base or the v0.10.0 amendment. Reviewers must evaluate
v0.10.1 as a whole; prior targets remain historical comparison points, not
assurance inherited by the new release.

## Patch delta

v0.10.1 does not change the DPoP protocol implementation introduced in
v0.10.0. It makes the existing server-wide enforcement contract independently
reviewable:

- A client registered with `dpop_bound_access_tokens=false` cannot bypass
  `DPoPConfig(require_bound_tokens=True)`.
- Authorization without `dpop_jkt` returns `invalid_request` and no code.
- Code exchange and public refresh without a valid proof return
  `invalid_dpop_proof` without consuming the usable credential.
- Successful access and refresh responses are DPoP-bound.
- A request-aware resource verifier enforces method, URL, key, access-token
  hash, proof time, and shared replay storage.
- A separate real workerd/WebCrypto + D1 isolate exercises the server-wide
  policy while the mixed DPoP and stable MCP Bearer profiles remain green.

This closes the selected ASVS `v5.0.0-10.3.5` and
`v5.0.0-10.4.14` evidence gap for deployments that enable the server-wide
profile and use `DPoPRequestVerifier` at every resource server.

## Residual and delegated risks

- DPoP remains opt-in. The default Bearer profile remains replayable after
  token disclosure.
- Server-provided DPoP nonce challenges are not implemented.
- All replicas and isolates must share an atomic replay store.
- A top-3000 policy-matching password set and current breach corpus remain
  deployment inputs; the compact built-in baseline is not presented as ASVS
  coverage.
- Rate limiting, recoverable-secret protection, administrative authorization,
  production Cloudflare configuration, TLS, logging, backup policy, and tenant
  isolation remain deployment responsibilities.
- PostgreSQL remains generated schema/migration coverage, not a shipped
  runtime adapter.

## Required reviewer treatment

Reproduce Profiles A–D in `audit/PROCEDURES.md`, inspect the complete

maintainer suite as an audit conclusion. Findings and the final report must
identify v0.10.1 by tag and commit and distinguish library, configured-profile,
and deployment responsibilities.
